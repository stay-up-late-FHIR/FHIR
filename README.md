## 故事情境


### 沉默的數據與凌晨三點的電話

台北信義計畫區的一棟商辦大樓裡，凌晨三點半，整座城市只剩下路燈和 24 小時便利商店還醒著。

雅婷正處於查帳旺季的地獄週。為了核對一筆跨國子公司的複雜帳目，她已經連續在座位上坐了 14 個小時。桌上堆滿了提神飲料空罐、冷掉的黑咖啡，以及散落的藥局成藥包裝。

「數字...為什麼對不起來...」她的聲音沙啞，手指在鍵盤上顫抖。

就在她喝下今晚第六杯濃縮咖啡試圖抵抗睡意時，心臟猛烈地「跳漏了一拍」，緊接著是一連串失控的狂跳。那種感覺不像是在運動，而像是有隻受驚的鳥被困在胸腔裡瘋狂衝撞。

雅婷感到一陣強烈的暈眩，視野開始變窄。她試圖伸手去拿水杯，卻無力地把杯子碰倒，整個人向前趴倒在充滿報表紙的桌面上。

#### 智慧手錶的「孤立」判斷

雅婷手上的智慧手錶是上一代的型號，沒有心電圖，動作感測器也因為設定問題關閉了。它不知道雅婷是坐著還是跑著，但它依然偵測到了足以觸發警報的致命訊號：

1. **極端的心率數值（Heart Rate）：**
感測器讀取到雅婷的心率在毫無預警的情況下，鎖死在 **175 bpm** 上下。
2. **血氧濃度（SpO2）異常：**
因為過度換氣與淺呼吸，她的血氧濃度開始出現波動，跌破了 95% 的安全線，來到 **91%**。
3. **時間與歷史數據的矛盾（Time Context）：**
這是手錶演算法最強大的依據。系統紀錄顯示，過去一個月，雅婷在凌晨 3:30 的心率通常是 60-70 bpm（睡眠或休息狀態）。現在這個時間點出現 175 bpm，即便是運動也是極不合理的異常值。

**手錶的邏輯判斷：**
「偵測到持續性極度心搏過速（>160bpm 持續 60 秒）。與歷史生理時鐘不符。血氧下降。觸發『使用者確認』機制。」

手錶劇烈震動，螢幕亮起紅燈，顯示巨大的文字：
*「偵測到異常高心率！您在運動嗎？若無回應將在 30 秒後發送求救訊號。」*

雅婷趴在桌上，意識模糊，根本無法抬手去按「我在運動」的按鈕。

#### FHIR 格式的純數據傳輸

30 秒倒數結束，無人回應。手錶判定為「喪失意識或危急狀態」。

手錶立即將僅有的幾項核心數據——**當下心率 (175 bpm)**、**血氧 (91%)**、**發生時間**、以及**GPS 座標**——打包成符合醫療標準的 **FHIR Observation** 資源格式。

```json
// 示意：非常精簡但關鍵的 FHIR 封包
{
  "resourceType": "Bundle",
  "entry": [
    {
      "resource": {
        "resourceType": "Observation",
        "code": { "text": "Heart Rate" },
        "valueQuantity": { "value": 175, "unit": "bpm" },
        "status": "critical"
      }
    },
    {
      "resource": {
        "resourceType": "Observation",
        "code": { "text": "SpO2" },
        "valueQuantity": { "value": 91, "unit": "%" }
      }
    }
  ]
}

```

這個封包透過 4G 網路發送到了與手錶連動的 24 小時遠距醫療中心。

#### 醫生端的盲測與直覺

在醫療中心，值班的張醫師接到了警報，他看到了三個關鍵資訊：

1. **心率 175**（非常高）。
2. **時間 03:32 AM**（非常不合理）。
3. **病人未回應手錶確認**（最關鍵的危險指標）。

「凌晨三點心跳 175，且沒有回應裝置確認...」張醫師迅速判斷，「不管是不是心律不整，這都必須視為休克或昏迷處理。」

#### 來自雲端的強制介入

張醫師立刻啟動了雙向通訊功能。

雅婷趴在桌上，忽然聽到手錶發出了極大聲的高頻警報音（這是醫生端強制開啟的「尋找/喚醒模式」），緊接著是擴音器傳來嚴肅的聲音：

**「雅婷小姐！我是醫療中心的張醫師！我們收到緊急訊號。如果您聽得到，請敲擊桌子或發出聲音！」**

雅婷勉強發出了一點呻吟聲。手錶的麥克風捕捉到了這個微弱的聲音。

張醫師聽到聲音後，立刻確認病人尚有意識但極度虛弱。他迅速透過系統發送了一組緊急處置的文字指令到手錶螢幕上（為了方便隨後趕到的旁人查看），並繼續用語音引導：

**「雅婷，聽我說，妳現在心跳過快。請試著『閉氣』，像是在用力排便一樣憋氣（Valsalva maneuver），這能幫助刺激迷走神經讓心跳慢下來。我已經通知救護車和妳的姊姊了。」**

#### 結局

十分鐘後，大樓夜間保全拿著備用鑰匙打開辦公室門時，看見雅婷正趴在桌上，依照手錶傳來的語音指示，艱難地進行憋氣動作。

救護人員趕到現場，看了一眼手錶螢幕上持續更新的 FHIR 數據：「心率 160，血氧 93」。雖然數據很少，但「持續的高心率」加上「凌晨發作」的情境，讓救護人員排除了恐慌症，直接針對心因性急症進行供氧與靜脈注射準備。

雅婷被送上救護車時，手錶震動了一下，顯示張醫師傳來的最後一條訊息：
*「生命徵象數據已交接給醫院。好好休息，工作不值得拿命換。」*

### 午夜驚魂

場景： 凌晨 3:30，台北某公寓。 林阿嬤（獨居）心臟不適觸發警報，並由醫生端確認需要急救。

子女端（大偉，40歲工程師）的情況： 大偉正在新竹家中熟睡，手機開啟了「勿擾模式（Do Not Disturb）」。 一般 App 的推播通知（Push Notification）這時候是發不出聲音的，通常會被靜音。

#### 系統介入：

突破勿擾模式： 醫療中心的系統撥出電話。大偉將「緊急醫療中心」的號碼設為「我的最愛（VIP）」，因此這通電話能突破勿擾模式，讓手機大聲響起。

語音內容： 大偉驚醒，接起電話。電話那頭不是冰冷的機器音，而是醫療中心值班人員（或極度擬真的 AI 語音）：

「請問是林阿嬤的緊急聯絡人陳大偉先生嗎？這裡是 24h 遠距醫療中心。您的母親剛才偵測到嚴重心律不整，醫生已確認風險，救護車正在前往台北市xx路xx號的途中。請您保持電話暢通，我們稍後會將醫院資訊透過簡訊傳送給您。」
